# 教練機率的校準報告

由 `npm run calibrate` 產生：電腦自戰 8000 局（每 5 局留 1 局只做驗證）。電腦知道每家真正的手牌，所以能直接數出「聽牌的比例」與「每種牌是對方要的牌的比例」。

> 對手是本程式的電腦（中級與高級各半），設定為有胡必胡，所以「放過的牌」在這些電腦身上實測 0 次放槍；這是模型前提，不是真人牌桌的安全保證——真人可能為了自摸或台數放過胡牌。教練不讀對手私密的過水狀態。

加權倍數（相對於同類牌）：他最近手切的牌附近 ×0.97；他攤牌做一色的那門／字牌 ×0.77；他一直在打的那門 ×0.56。倍數在 0.9～1.1 之間代表對本程式的電腦看不出差別，教練就不會把它當成理由（真人可能不同）。

## 胡牌與台數

- 一般胡牌（非莊家、沒做一色）平均 2.03 台；全部胡牌平均 2.21 台；自摸占 27.0%。
- 手牌價值（handvalue.js）還沒聽牌時看不到的零碎台數（暗刻、獨聽、平胡等），平均 0.5 台。
- 自己「進聽數 × 有效牌 × 牌牆剩餘」對應的最後胡牌比例共 81 組，供攻守期望值使用。

## 實戰驗證：照教練打有沒有比較好

`node scripts/evaluate-coach.cjs`：同一副牌打兩次，0 號位一次「照教練打」（出牌與吃碰都聽決策核心），一次「只看牌效率」（中級電腦），另外三家相同。輸出同一副牌兩種打法的得失差與標準誤。

### 目前版本（邏輯迴歸模型，4000 局，種子 801–4800）

| 0 號位 | 胡牌 | 放槍 | 每局得失差（教練 − 效率，台，含底） |
|---|---|---|---|
| 照教練打 | 25.3% | 14.9% | +0.06 ± 0.10（標準誤） |
| 只看牌效率 | 26.1% | 20.0% | |

- **放槍明顯減少**：少 5 個百分點（約少四分之一），四組各 1000 局都一致。
- **胡牌略少**：約少 0.8 個百分點。
- **每局得失**：+0.06 台，但標準誤 0.10，**統計上看不出比只看牌效率更會贏錢**。

結論：教練目前的價值在「少放槍」與「解說為什麼」，還不能宣稱「照著打會贏更多」。要把少放槍變成多得分，下一步是讓台數進入決策（自己胡牌的台數目前只用平均值），以及「決定守就守到底」。

### 注意雜訊

每副牌的得失起伏很大：同樣「只看牌效率」，種子 1–400 平均 +0.86 台、401–800 平均 −0.07 台。400 或 800 局只能看大方向，差距小於約 0.3 台時分不出好壞；調整攻守門檻之類的比較要用數千局並看標準誤。

### 開發過程中的紀錄

- 攻守期望值第一版把「三進聽以上」都算同一組，離聽牌更遠的打法因為有效牌張數較多，反而被估成更容易胡，教練會在沒人威脅時亂拆牌（胡牌率掉到 24.8%）。修正後才正常。
- 邏輯迴歸讓預測變準（見上方），但 800 局的小樣本看不出實戰差異；4000 局的結果如上表。
